# SahandVPN 1.11 Upgrade Path - Verification Summary

## 1.10 baseline (HEAD commit: 0d67c54)

### 1.10: Simple Menu Consolidation
- Single-action VPN: One central ring (connect/search) with cancel/disconnect states.
- Settings menu: Three separate dialogs from user side:
  * UpdateDialog (update/downl) from UpdateViewModel: one dismiss-only screen; download starts auto-install UI.
  * ThemeDialog: separate UI (showTheme/AlertDialog) to ThemeManager.setThemeMode().
  * LanguageDialog: from UI (showLanguageDialog/AlertDialog) with Vazirmatn options.
  * KillSwitchDialog: separate UI (showKillSwitch/AlertDialog) with system-status query.
  * DetailsDialog: separate UI (showDetails/AlertDialog) with language/kill-switch links.

### 1.10 improvements (overview):
- SingleActionPolicy added (flow, token, requested/searching, accepts/cancel logic).
- Theme persistence via ThemeManager, applied to entire surface.
- Language support: Persian/English/system via AppLocaleManager.
- Kill-switch dialog: system status query from CoreVpnService via Messenger.
- UpdateDialog: contained download, check, auto-install flows (no separate settings).
- Simplified branching: booted/testing/downl/connect/scanning flags.
- Overall reduced UI complexity but dialogs remain separate (not consolidated).

### 1.11 targets (required and new):

1. **Single settings menu consolidation** (1.11 must consolidate separate dialogs)
   - Merge: UpdateDialog + ThemeDialog + LanguageDialog + KillSwitchDialog + DetailsDialog
   - One screen (consolidated dialog) with tabs/sections or a unified drawer.
   - Preserve functionality: update actions, theme choices, language, kill-switch view, diagnostic export.
   - Replace: showDetails/showTheme/showKillSwitch/showLanguageDialog/showDisconnectWarning
   - Implementation: keep consolidated UI; keep all underlying functions (querySystemVpnStatus, launchUpdateInstaller, ThemeManager.setThemeMode, AppLocaleManager.setApplicationLanguage, diagnostic export if new).
   - Must NOT break any existing behavior or interaction flow.

2. **Diagnostic report export with timer and RX/TX counters** (1.11 must add)
   - Measure actual tunnel traffic: TrafficStats.getTotalRxBytes(), getTotalTxBytes() when VPN connected.
   - Compare against "estimated" (e.g., from connections count). Label as VPN-specific vs estimated.
   - Export report: offer as a user action (likely in details menu) to generate a report containing:
       * Connection duration (timer)
       * RX/TX bytes
       * Label (actual vs estimated) and source method.
       * Redacted (no secrets/identifiers).
       * File format: JSON or plaintext with human-readable labels.
   - Use android.os.SystemClock.uptimeMillis() for connection start timestamp.
   - Store report in cacheDir/diagnostics/ (redacted) and allow user to read/send via Telegram.

3. **Endpoint choice using persisted success/failure history and cooldown**
   - In SimpleProbeEngine.probe, maintain per-endpoint history: success count, failure count, last attempt timestamp.
   - When building endpoints list, skip those in cooldown (e.g., last failure < 5 min) or low success rate.
   - Adjust SimpleConfig.Winner sorting: weighted by delay + success history.
   - Implement in SimpleConfig.pruneWinners and SimpleProbeEngine selection logic.

4. **Resource tuning: bound concurrency/cache subscription downloads/health intervals**
   - Current: TCP_CONCURRENCY=8, SCAN_CHUNK=120, TARGET_WORKING=5.
   - Consider tuning: lower TCP_CONCURRENCY to reduce battery (e.g., 4).
   - Cache: UpdateViewModel check interval: currently 6h success, 15m failure; consider longer.
   - Subscription sync interval: SimpleConfig.SUB_URL sync per connection (keep existing).
   - Reduce polling frequency in SimpleTestService (e.g., increase poller delay).
   - Bound max subscriptions processed per run (e.g., MAX_ENDPOINTS_PER_RUN) earlier already limited.

5. **Reject unsafe TLS configs/cert validation bypass, sanitize logs**
   - UpdateCheckerManager: strict HTTPS only, reject redirects to non-github/CDN hosts, keep only TLS-verified endpoints.
   - SimpleProbeEngine: reject outbounds with allowInsecure TLS (already implemented in isSupportedOutbound: allowInsecure check).
   - Core runtime: ensure libv2ray.aar is used, no manual config bypass.
   - Logs: sanitize logs in LogUtil: redact URLs, IPs, authentication tokens. Do not log endpoints with credentials.
   - Use existing: LogUtil.e/w but add filtering for sensitive patterns.

6. **Actual DNS/IPv6/leak review/testing and fix identified issues**
   - Implement leak tests: small test helper APK or browser inside tunnel through controlled endpoints (e.g., http://ifconfig.me/ip, http://ipv6-test.com).
   - Capture actual app UID traffic via tunnel and compare with direct socket.
   - For emulator, tests possible; note physical phone not tested.
   - For IPv6: test via IPv6-capable endpoints; verify routing.
   - Use: check for DNS leaks by querying system DNS settings.
   - Ideally, add unit tests for leak detection but not required.

7. **State preservation on cancellation and restore**
   - Ensure SimpleConfig.restoreIfEmpty on cancelTest, fallback correctly.
   - Ensure flow.cancel() resets requested/searching appropriately.
   - Ensure backup and winners persistence works as before.

8. **UI/UX consistency**
   - Unified settings screen: one drawer/expanded section from home, not separate icons (already present 1.10).
   - Light/dark mode: persist theme across settings, updates.
   - No fake metrics: ensure counters are real.

9. **Stability and reliability**
   - Verify connection handover handling (WiFi <-> cellular) for emulator (if possible).
   - Screen off / battery restrictions: maintain test service background limits (work manager?). n o changes.
   - Emulator stability: ensure SimpleTestService doesn't crash under high load (already capped concurrency).

10. **New: actual connection timer and RX/TX counters**
    - In CoreVpnService: store start time, collect traffic stats on broadcast.
    - SimpleActivity: expose counters via dialog/report.
    - Add redaction: report sanitized (no secrets).

11. **Build artifacts and release preparation**
    - Create signed release APK for 1.11 with versionCode bump from 10011 to 10012, versionName "1.11".
    - Same keystore, same signing config.
    - Ensure BuildGradle kts has updated versionName.
    - Build process: same gradle tasks, maybe add a task for diagnostics export.
    - Create GitHub Release v1.11 with changelog documenting added items.
    - Publish APK to Telegram (outside repo) for parent verification.
